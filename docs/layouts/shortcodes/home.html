What is Valet?

Validate files before ingestion.

Valet is a command-line data quality gate for file-based pipelines. Check incoming files against your rules, then use its JSON report and exit code to decide whether ingestion proceeds.

Why Valet?

Make data quality a pipeline step.

A readable file can still have missing IDs, duplicate keys, invalid values or an unexpected schema. Check those requirements at the handoff, before your lakehouse, warehouse or downstream job has to deal with them.

01

Check more than the file format

Validate required values, ranges, keys, references, column relationships and dataset totals against declared rules.

02

Keep rules with your pipeline

Describe checks in YAML or JSON. Version and reuse the same configuration instead of maintaining a validation script for each input.

03

Give the caller a clear result

Get an aggregate JSON report on stdout and use the exit code as your gate. No output files are created unless requested.

04

Investigate failures when needed

Explicitly request row-level issues and Parquet or CSV outputs, with provenance connecting failures to their source rows.

05

Run without another service

Use one self-contained CLI for local or S3-compatible files. Streaming execution shares a managed-memory budget.

06

Inspect a Parquet schema separately

Only need column names and types? Use the metadata-only schema command; its report makes clear that values were not checked.

Your pipeline still owns ingestion.

Valet is not a lakehouse uploader, scheduler or storage platform. Keep your existing tools and put a validation gate before the next step. Use error-level rules for checks that must block ingestion; warnings alone do not block.
